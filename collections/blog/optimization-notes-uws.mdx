# Optimizing Uy Web Studio: From Heavy 3D Orbitals to Sub-Second Mobile Feeds

High-impact motion design and cutting-edge visual experiences often exist in tension with web performance. When Uy Web Studio launched its experiential portfolio featuring orbiting 3D WebGL meshes, dynamically decoded video textures, and duotone shader pipelines, the desktop experience was deeply engaging. 

However, mobile audits revealed severe performance bottlenecks:
- **Over 18 MB raw media payload** loaded across 5 concurrent uncompressed MP4 video textures.
- **Render-blocking font chains** resulting in noticeable First Contentful Paint (FCP) delays.
- **Continuous GPU/CPU strain on mobile devices** caused by Three.js render loops, shader compilation, and simultaneous video decoding.
- **Fragmented touch navigation** where vertical and horizontal mobile gestures collided with 3D raycasting.

This case study documents the end-to-end performance overhaul that reduced page payloads by **over 90%**, eliminated main-thread blocking on mobile viewports, and delivered a bespoke, touch-native card feed featuring custom draggable scroll telemetry and GPU-composited duotone micro-interactions.

---

## 1. Architectural Strategy: Dual-Tier Rendering

### The Challenge with "Responsive" 3D
A common mistake in experiential web development is attempting to force a complex 3D WebGL scene onto mobile screens simply by scaling down the viewport camera or reducing mesh polygon counts. 

On mobile devices, Three.js WebGL contexts still incur severe penalties:
1. **Memory Allocation**: Instantiating WebGL contexts and uploading video textures to GPU VRAM consumes precious mobile memory.
2. **Battery & Thermals**: Looping `requestAnimationFrame` render passes and hardware video decoding drain battery rapidly.
3. **Gesture Conflicts**: Touch-dragging across a 3D orbit field conflicts with standard vertical mobile page scrolling.

### The Solution: Option B Architecture
Instead of running a throttled 3D scene on mobile, we engineered a clean **Dual-Tier Rendering Architecture** in `app/work/WorkPageClient.tsx`:

```tsx
// iteration-charizard/app/work/WorkPageClient.tsx
export default function WorkPageClient({ projects }: { projects: WorkProject[] }) {
  const [isMobileLayout, setIsMobileLayout] = useState(false);

  useEffect(() => {
    const updateLayout = () => {
      const prefersReduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
      const isMobile = window.innerWidth < 768;
      setIsMobileLayout(prefersReduced || isMobile);
    };
    updateLayout();
    window.addEventListener('resize', updateLayout);
    return () => window.removeEventListener('resize', updateLayout);
  }, []);

  return (
    <>
      <GrainOverlayMount opacity={0.05} />
      <BrandNav title="Work" links={SITE_NAV_LINKS} />
      {isMobileLayout ? (
        <main className="uy2-container" style={{ paddingTop: '7rem', paddingBottom: '5rem' }}>
          <div className="uy2-mobile-feed">
            {/* Native DOM card feed with zero 3D overhead */}
            {projects.map(({ slug, frontmatter }) => (
              <article key={slug} className="uy2-work-card">
                <CardMediaScroller images={frontmatter.images} />
                <Link href={`/work/${slug}`} className="uy2-work-card-link">
                  ...
                </Link>
              </article>
            ))}
          </div>
        </main>
      ) : (
        <PortfolioOrbitFieldMount projects={orbitProjects} />
      )}
    </>
  );
}
```

By completely gating the mount of `PortfolioOrbitFieldMount`, mobile devices execute **zero WebGL draw calls**, allocate **zero Three.js texture buffers**, and mount **zero hidden video elements**.

## 2. Media Payload Engineering: Slashing 18 MB to 1.4 MB

The largest bottleneck identified in our Lighthouse audit was the sheer size of the video textures used for interactive mesh surfaces. The original assets were converted directly from high-framerate screen recordings with loose compression parameters.

### Targeted Transcoding Pipeline
We constructed an automated Node.js and `ffmpeg` media conversion utility (`scripts/convert-media.mjs`) targeting the actual physical render resolution of the display meshes:
- Scaled dimensions down to `--width 360–480` (sufficient for 2x retina mobile displays and 3D mesh UV bounds).
- Applied Constant Rate Factor (`-crf 28–30`) with `libx264` and `preset: slow`.
- Stripped unused audio channels (`-an`).
- Enforced `pix_fmt yuv420p` for universal hardware decoder compatibility.

```bash
# Automated transcoding command executed per video texture
ffmpeg -i raw-recording.mp4 \
  -vf "scale=480:-2:flags=lanczos" \
  -c:v libx264 -crf 28 -preset slow -pix_fmt yuv420p \
  -movflags +faststart -an optimized-recording.mp4
```

### Video Payload Optimization Results

| Asset Name | Original Size | Optimized Size | Reduction |
| :--- | :--- | :--- | :--- |
| `janel-desktop-recording.mp4` | 9.16 MB | **351 KB** | **96.2%** |
| `janel-mobile-recording.mp4` | 3.75 MB | **835 KB** | **77.7%** |
| `photographer-desktop.mp4` | 4.33 MB | **211 KB** | **95.1%** |

## 3. Typography & Critical Path Optimization

### The Google Fonts Bottleneck
Previously, `app/layout.tsx` loaded external typography via standard HTML link tags pointing to `fonts.googleapis.com` and `fonts.gstatic.com`. 

This introduced a classic multi-hop critical-path waterfall:
1. DNS lookup, TCP handshake, and TLS negotiation with `fonts.googleapis.com`.
2. Render-blocking CSS stylesheet download and parse.
3. Subsequent font file downloads from `fonts.gstatic.com`.

### Migrating to `next/font/google`
We converted all typography (`Archivo Black`, `Inter`, and `Space Mono`) to Next.js's built-in self-hosting font loader with `display: 'swap'`:

```tsx
// iteration-charizard/app/layout.tsx
import { Archivo_Black, Inter, Space_Mono } from 'next/font/google';

const archivoBlack = Archivo_Black({
  weight: '400',
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-heading-next',
});

const inter = Inter({
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-body-next',
});

const spaceMono = Space_Mono({
  weight: ['400', '700'],
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-mono-next',
});
```

To bridge Next.js's hashed font variables into our design token system without causing circular resolution issues, we mapped them in `lib/tokens.css`:

```css
/* iteration-charizard/lib/tokens.css */
:root {
  --font-heading: var(--font-heading-next, 'Archivo Black', sans-serif);
  --font-body: var(--font-body-next, 'Inter', -apple-system, sans-serif);
  --font-mono: var(--font-mono-next, 'Space Mono', monospace);
}
```

This ensures font files are pre-downloaded at build time and served directly from the same static origin, removing all external blocking requests.

## 4. Lifecycle & Execution Gating

Even on desktop viewports where the 3D WebGL orbit scene is active, running high-framerate rendering in backgrounded tabs wastes device resources and triggers thermal throttling.

### Tab Visibility Awareness
We integrated `document.visibilitychange` event listeners in both `PortfolioOrbitFieldMount.tsx` and the core 3D engine `lib/portfolio-orbit-field.js`:

```javascript
// iteration-charizard/lib/portfolio-orbit-field.js
export function createPortfolioOrbitField(container, options) {
  let isPaused = false;
  let rafId = null;

  function handleVisibilityChange() {
    if (document.hidden) {
      pause();
    } else {
      resume();
    }
  }

  function pause() {
    isPaused = true;
    if (rafId) cancelAnimationFrame(rafId);
    // Pause all underlying video decoders
    videoElements.forEach(v => v.pause());
  }

  function resume() {
    if (!isPaused) return;
    isPaused = false;
    videoElements.forEach(v => v.play().catch(() => {}));
    rafId = requestAnimationFrame(render);
  }

  document.addEventListener('visibilitychange', handleVisibilityChange);
}
```

### Staggered Video Initialization
Triggering playback on 5 video decoders simultaneously at page load produces an immediate spike in JavaScript main-thread execution and hardware decoder contention. We staggered initial playback start times:

```javascript
// Stagger video play invocations by 120ms intervals
videos.forEach((video, index) => {
  setTimeout(() => {
    video.play().catch(() => {});
  }, index * 120);
});
```

## 5. Mobile Interaction Design: Custom Draggable Scrollbars & Duotone Hover

On mobile devices, having a smooth, touch-friendly, and brand-expressive card experience was paramount.

### Draggable Custom Scroll Telemetry
Rather than relying on OS-native scrollbars that look inconsistent across platforms, we designed a custom interactive scrollbar embedded directly between two mini brand logo buttons:

```tsx
// iteration-charizard/app/work/WorkPageClient.tsx (CardMediaScroller)
function CardMediaScroller({ images }: { images: string[] }) {
  const scrollRef = useRef<HTMLDivElement>(null);
  const trackRef = useRef<HTMLDivElement>(null);
  const [thumbState, setThumbState] = useState({ left: 0, width: 35 });
  const isDraggingRef = useRef(false);
  const dragStartXRef = useRef(0);
  const dragStartScrollLeftRef = useRef(0);

  const updateThumb = useCallback(() => {
    const el = scrollRef.current;
    if (!el) return;
    const { scrollLeft, scrollWidth, clientWidth } = el;
    const maxScroll = scrollWidth - clientWidth;
    if (maxScroll <= 0) {
      setThumbState({ left: 0, width: 100 });
      return;
    }
    const visibleRatio = clientWidth / scrollWidth;
    const thumbWidth = Math.max(18, Math.min(80, visibleRatio * 100));
    const scrollRatio = Math.max(0, Math.min(1, scrollLeft / maxScroll));
    const thumbLeft = scrollRatio * (100 - thumbWidth);
    setThumbState({ left: thumbLeft, width: thumbWidth });
  }, []);

  // Pointer drag event handlers with native setPointerCapture
  const handleThumbPointerDown = (e: React.PointerEvent<HTMLDivElement>) => {
    e.preventDefault();
    e.stopPropagation();
    (e.target as HTMLElement).setPointerCapture(e.pointerId);
    isDraggingRef.current = true;
    dragStartXRef.current = e.clientX;
    dragStartScrollLeftRef.current = scrollRef.current?.scrollLeft ?? 0;
  };

  const handleThumbPointerMove = (e: React.PointerEvent<HTMLDivElement>) => {
    if (!isDraggingRef.current || !trackRef.current || !scrollRef.current) return;
    const deltaX = e.clientX - dragStartXRef.current;
    const trackWidth = trackRef.current.clientWidth;
    const maxScroll = scrollRef.current.scrollWidth - scrollRef.current.clientWidth;
    const effectiveTrack = trackWidth * (1 - thumbState.width / 100);
    if (effectiveTrack > 0) {
      scrollRef.current.scrollLeft = dragStartScrollLeftRef.current + (deltaX / effectiveTrack) * maxScroll;
    }
  };
}
```

### Reactive Height Scaling (Zero Cropping)
To ensure cards render vertical mobile screenshots, widescreen mockups, and logos without awkward cropping, we transitioned from fixed rectangular crops (`object-fit: cover`) to fluid, height-constrained containers:

```css
.uy2-card-media-item img {
  height: clamp(100px, 22vw, 125px);
  width: auto;
  max-width: none;
  object-fit: contain;
  display: block;

```

### Replicating the WebGL Duotone Shader in CSS
In the desktop 3D scene, meshes rest in a stylized duotone tint and ease into full color upon cursor hover. We replicated this exact behavior across the entire DOM card component using pure GPU-composited CSS filters and transitions:

```css
/* Card in Duotone resting state */
.uy2-work-card .uy2-card-media-item img {
  filter: grayscale(100%) contrast(115%) brightness(88%);
  opacity: 0.85;
  transition: filter 0.32s cubic-bezier(0.2, 0.8, 0.2, 1),
              opacity 0.32s cubic-bezier(0.2, 0.8, 0.2, 1);
}

.uy2-work-card .uy2-card-media-item::after {
  content: '';
  position: absolute;
  inset: 0;
  background: var(--uy2-teal);
  mix-blend-mode: color;
  opacity: 0.35;
  pointer-events: none;
  transition: opacity 0.32s cubic-bezier(0.2, 0.8, 0.2, 1);
}

/* Card Hover: Synchronized illumination across images, scrollbars, and typography */
.uy2-work-card:hover .uy2-card-media-item img {
  filter: grayscale(0%) contrast(100%) brightness(100%);
  opacity: 1;
}

.uy2-work-card:hover .uy2-card-media-item::after {
  opacity: 0;
}

.uy2-work-card:hover .uy2-custom-scroll-thumb {
  background: var(--uy2-teal);

}

  color: var(--uy2-teal);
}
```

## 7. Key Takeaways for High-End Motion Architecture

1. **Bypass Rather than Throttle**: Don't force heavy 3D canvases onto small touch devices. Serving an intentionally designed DOM alternative preserves device battery and delivers superior UX.
2. **Compress Textures to Mesh Dimensions**: Videos rendered inside 3D mesh UVs or thumbnail cards don't require 1080p source resolutions. Right-sizing dimensions to actual display bounds slashes payloads by over 90%.
3. **Compositor Over JavaScript**: Dynamic visual effects (duotone tints, color reveals, glow elevations) should be expressed via GPU-accelerated CSS properties (`filter`, `opacity`, `transform`) rather than JavaScript math loops.
4. **Decouple Touch Controls from Navigation Links**: When designing horizontal scrollers inside clickable parent cards, isolate interactive controls outside the routing anchor to avoid frustrating accidental page navigations.
